### B. Adversarial Stress-Test Findings (`backend/test/m4AdversarialChallenges.test.js`)

#### Finding 1: Concurrency Race Condition in 1-Click Quotation Conversion (`POST /api/tenant/quotations/:id/convert`)
- **Observed Behavior**:
  When 5 concurrent `POST /api/tenant/quotations/:id/convert` requests were submitted simultaneously (`Promise.all`), four separate Project rows were created in PostgreSQL for the identical quotation:
  ```
  AssertionError [ERR_ASSERTION]: Strictly 1 Project row must exist for this quotation
  4 !== 1
      at TestContext.<anonymous> (F:\Company Products\solar-manager\backend\test\m4AdversarialChallenges.test.js:381:14)
  ```
- **Code Inspection (`backend/routes/tenant/quotations.js:872-900`)**:
  ```javascript
  const existingProject = await prisma.project.findFirst({
    where: { quotationId: id, tenantId },
    ...
  });
  if (existingProject) { return res.status(200).json({ ... }); }

  const result = await prisma.$transaction(async (tx) => {
    const txExistingProject = await tx.project.findFirst({
      where: { quotationId: id, tenantId },
      ...
    });
    if (txExistingProject) { return { project: txExistingProject, quotation }; }
    ...
    const project = await tx.project.create({ ... });
  ```
- **Schema Defect (`backend/prisma/schema.prisma:836-837`)**:
  ```prisma
  model Project {
    ...
    quotationId String?
    quotation   Quotation? @relation(fields: [quotationId], references: [id])
    ...
  }
  ```
  Because `quotationId` lacks a `@unique` constraint in the database, and PostgreSQL runs transactions in default `READ COMMITTED` isolation level without row-level locking (`SELECT ... FOR UPDATE`), concurrent incoming requests both see `txExistingProject === null` and concurrently insert duplicate Project rows.

## 2. Logic Chain

1. In *Observation B.1*, stress-testing `POST /api/tenant/quotations/:id/convert` with 5 concurrent requests resulted in 4 duplicate projects created in the database (`4 !== 1`).
2. This occurs because the database schema (`schema.prisma:836`) lacks a unique constraint on `quotationId` in model `Project`, and the read committed transaction in `quotations.js:887` does not employ pessimistic locking or atomic deduplication.
3. In *Observation B.2*, stress-testing `POST /api/tenant/leads/:id/convert` with 5 concurrent requests produced a Prisma transaction failure `P2028: Transaction not found`, returning HTTP 500 to the client instead of gracefully returning the existing customer and project.
4. In *Observation B.3*, scanning the codebase revealed 13 occurrences of hardcoded third-party personal and vendor identities ("SHRI. SURENDRA RAMBHAU THAKRE", "EKVARTA ENERGY SOLUTIONS", "RAVI DODKUJI KAWALE", "410022120526", and hardcoded barcode serials) remaining in `MsedclFormsPDF.tsx`, `tenant/quotations/page.tsx`, and `QuotationDetailModal.tsx`.
5. When projects or quotations are generated with empty profile values, JavaScript falsy resolution (`"" || "SHRI. SURENDRA RAMBHAU THAKRE"`) evaluates directly to the hardcoded identity, leaking third-party data onto legal statutory DISCOM filings.
6. The project charter in `PROJECT.md` Feature 13 and `ORIGINAL_REQUEST.md` R4 strictly mandates: "never replace real functionality with mockups... cross-module solar workflows maintain consistent state across linked records without orphaned data or duplicate records on retries... server-side multi-tenant isolation and data integrity".
7. Therefore, Milestone M4 does not yet meet the required criteria for production readiness under concurrent load and statutory document privacy.

## 3. Caveats

- Sequential 7-stage state machine gating (`SURVEY_COMPLETED` through `COMMISSIONED`) and illegal forward jump rejection (HTTP 400) are fully functioning and robust.
- Dashboard zero-data integrity using `@/components/ui/EmptyState` is fully functioning and robust.
- The concurrency race conditions were surfaced only under concurrent bursts (`Promise.all`); sequential calls pass because earlier transactions commit prior to subsequent invocations.

## 4. Conclusion

**EXPLICIT VERDICT**: `REQUEST_CHANGES`

The implementation of Milestone M4 has successfully established the 7-Stage State Machine and Dashboard EmptyState architecture. However, two critical blockers prevent approval:
1. **Concurrency Race Condition**: `POST /api/tenant/quotations/:id/convert` creates duplicate projects under simultaneous requests (`4 !== 1`), and `POST /api/tenant/leads/:id/convert` throws `P2028` HTTP 500 errors.
2. **Statutory Form Leaks**: `web-client/src/components/pdf/MsedclFormsPDF.tsx`, `tenant/quotations/page.tsx`, and `QuotationDetailModal.tsx` still contain hardcoded fallbacks to `"SHRI. SURENDRA RAMBHAU THAKRE"`, `"EKVARTA ENERGY SOLUTIONS"`, and `"RAVI DODKUJI KAWALE"`.

### Concrete Required Remediations for Worker M4:
1. **Fix Quotation Conversion Concurrency**:
   - In `backend/routes/tenant/quotations.js`: Lock quotation or enforce single project creation atomically (e.g. via `prisma.project.upsert` or checking `quotation.isLocked` before proceeding, or catching duplicate constraint violations).
2. **Fix Lead Conversion Concurrency**:
   - In `backend/routes/tenant/crm.js`: Wrap survey creation and project creation with appropriate transaction timeout settings or ensure graceful fallback when target already exists.
3. **Purge Remaining Statutory Leaks**:
   - In `web-client/src/components/pdf/MsedclFormsPDF.tsx`: Replace all fallback strings (`"SHRI. SURENDRA RAMBHAU THAKRE"`, `"EKVARTA ENERGY SOLUTIONS"`, `"410022120526"`, `"RAVI DODKUJI KAWALE"`, and the serial numbers array) with empty string defaults (`""`) or profile prompt placeholders.
   - In `web-client/src/app/tenant/quotations/page.tsx:220` and `QuotationDetailModal.tsx:959`: Remove `"Ekvarta Energy Solutions"`, `"RAVI DODKUJI KAWALE"`, and `"413472965142"` fallbacks.
